## 7. Final Devpost Field Map

### Project Title
`RouteWitness (AccessGraph): Deterministic Accessibility Release Twin with GitLab Duo`

### Elevator Pitch (One-sentence summary - 160 characters max)
*A machine-verifiable release twin that prevents transit accessibility regressions in GitLab CI/CD, pairing GitLab Duo risk hypotheses with deterministic policy gates.*

### About the Project

#### The Problem
Modern universities, transit systems, and corporate facilities frequently publish digital maps for wayfinding. However, software updates and routine maintenance schedules frequently introduce silent accessibility regressions: elevator shutdowns, construction closures, or ramp detours that sever paths for wheelchair users or mobility-impaired students. Because conventional CI/CD tests only test code syntax and generic unit behavior, these physical accessibility impasses slip into production unnoticed.

#### What It Does
**RouteWitness** creates an evidence-backed digital release twin for accessible physical infrastructure:
1. **Deterministic Accessibility Policy:** Evaluates multi-objective graph reachability against strict hard constraints (stairs prohibition, max slope, surface type, minimum door width) across an 8-scenario benchmark matrix.
2. **GitLab Duo Flow Integration:** When a merge request alters physical infrastructure, GitLab Duo inspects the AST diff, maps affected topological nodes, and generates explanatory risk hypotheses.
3. **Deterministic Separation of Powers:** The AI investigates and explains, but the pure TypeScript routing engine deterministically owns the `PASS` or `BLOCK` verdict.
4. **Minimal Counterexample Reducer:** When a regression occurs, RouteWitness isolates the single minimal journey that broke, eliminating reviewer diagnostic fatigue.
5. **Tamper-Evident Release Receipt:** Binds the commit SHA, policy hash, and full verification evidence into a checksummed receipt for supervised human promotion.

#### How We Built It
- **Core Domain & Verification:** Pure TypeScript routing engine with 4-key deterministic tie-breaker, multi-objective cost optimization, and topological Access Debt auditing.
- **Testing & Accessibility:** 85 Vitest unit tests with 82.31% statement coverage and 79.54% branch coverage; 50 Playwright E2E browser executions with automated Axe core audits reporting 0 violations across 5 states and 5 viewports.
- **GitLab CI/CD:** 10-stage pipeline (`.gitlab-ci.yml`) covering provenance, typecheck, lint, policy integrity, unit tests, golden regression, counterfactual comparison, security audit, secret scanning, and release receipt synthesis.
- **GitLab Duo Custom Flow:** Declarative Duo flow (`.gitlab/duo/flows/route-witness.yml`) configuring read-only Impact Analyst and Reporter roles with strict local path boundaries.

#### Challenges We Overcame
1. **Preventing AI Hallucinations in Safety Gates:** Large language models frequently hallucinate reachability in complex graph topologies. We solved this with a strict architectural boundary: LLMs only produce explanatory narrative and risk hypotheses; deterministic code computes the reachability proof.
2. **Eliminating Reviewer Fatigue:** A single broken lift can cause 20+ benchmark trips to fail. We developed a minimality reduction algorithm that ranks and isolates the single shortest, fewest-barrier counterexample for developer review.
3. **Honest Lifecycle Evidence:** Rather than claiming 100% cloud coverage with mock endpoints, we engineered an honest evidence status model distinguishing `MEASURED`, `HUMAN_APPROVAL_REQUIRED`, and unexecuted cloud stages (`NOT_MEASURED`).

#### What We Learned
Accessible wayfinding is not merely a pathfinding problem—it is a governance and infrastructure prioritization problem. By quantifying accessibility barriers as "Access Debt" and enforcing hard invariants in the CI/CD pipeline, institutions can make accessibility a measurable, non-negotiable release criterion.
